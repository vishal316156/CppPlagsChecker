PlagCheck
C++ similarity analysis

User Manual

A short guide to comparing C++ submissions and testing the similarity engine.

1. What is PlagCheck?

PlagCheck compares two C++ programs and measures their structural similarity.

  • Token normalization
  • 5-token and 15-token n-grams
  • Jaccard similarity
  • Winnowing fingerprints
Important: A high similarity score is a review signal, not proof of plagiarism. Very short programs can produce high scores because they contain fewer unique patterns.

2. Manual Code Comparison

  1. Enter the first C++ program in Code A.
  2. Enter the second program in Code B.
  3. Click Compare.
  4. Review the similarity result, N-gram score, and Winnowing score.

For meaningful results, compare programs that solve the same problem.

3. Run the Benchmark

Don't have two programs available? Use the built-in benchmark.

  1. Click Run Benchmark.
  2. PlagCheck processes 10 predefined C++ code pairs.
  3. Review Precision, Recall, F1 Score, and Cases Passed.
  4. Click any test case to expand it.
  5. Inspect Code A, Code B, and their similarity scores.

4. What Does the Benchmark Test?

The benchmark checks common transformations that can make copied code look different:

  • Variable renaming
  • Literal changes
  • Comment and formatting changes
  • Dead-code insertion
  • Statement reordering
  • for → while rewriting

It also contains unrelated programs to check whether the detector incorrectly flags different algorithms.

5. Understanding the Scores

N-gram Similarity

Measures overlap between sequences of normalized code tokens.

Winnowing Similarity

Compares fingerprints selected from the token sequence.

6. Manual Testing

Modify one aspect of a program at a time:

Original Code → Rename variables → Change literals → Add/change comments → Reorder statements → Rewrite a loop → Compare with original

7. Important Limitation

Original Code → Rename variables → Change literals → Add/change comments → Reorder statements → Rewrite a loop → Compare with original

A high score can occur because:

  • Programs use common programming patterns.
  • Both solutions implement the same standard algorithm.
  • The submitted programs are very short.

Treat flagged results as indicators for further review, not a final verdict.
